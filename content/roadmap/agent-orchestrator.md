---
title: Hand a ticket to an agent and walk away
stage: planned
category: agents
outcome: Ship a small ticket without sitting next to the agent
summary:
  A harness that picks up an issue, works it end to end, and comes back to you
  only when it is genuinely stuck.
question: Which of your tickets would you let an agent take unattended?
---

Working with a coding agent still means watching it. You hand it a task, then
stay to answer the questions it cannot answer itself, which caps what it is
worth handing over in the first place.

The orchestrator sits against the issue tracker instead of against you. It takes
a card, works it through, and stops to ask only when it actually needs a
decision, rather than at every fork. Linear first, since that is where the work
already is.

Being interrupted is part of the design, not a failure of it. An agent that
guesses at an ambiguous ticket produces work someone has to unpick, so asking is
the cheaper outcome and the harness is built to make asking easy.

A proof of concept exists and needs bringing back into shape before any of the
above is worth judging.
